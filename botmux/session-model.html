      #会话与话题模型

      在 botmux 里，一个会话 = 一个正在运行的 AI 编程 CLI 进程（如 Claude Code、Codex）+ 它的上下文。你发的每条消息都会落进某个会话。

      「为什么每次 @ 都像重新开始」「新群怎么拿不到之前的聊天」这类问题，根子都在「消息落到了哪个会话」。这一页讲清楚这件事，以及怎么新开、复用、找回会话。

      #一眼看懂：消息落到哪个会话

      你在哪儿聊默认怎么分会话想改怎么办
      话题群每个话题一个会话，话题之间互不影响不用设置，最推荐
      普通群群里顶层 @ 机器人的消息共用一个会话；群里开出来的话题各自一个会话/reply-mode，见下文「普通群」
      私聊和机器人的整个私聊是一个连续会话/reply-mode，见下文「私聊」
      /g 建的会话群整个群一个会话见 一键新建会话群
      Oncall 群绑定到一个项目目录，群里所有人 @ 就能问见 Oncall 模式

      会话是按机器人分开的。同一个话题里 @ 了两个机器人，就是两个各自独立的会话，上下文不共享。

      #话题群

      每发一个新话题，就开一个新会话；在话题里回复，就是在同一个会话里接着聊。不同话题完全隔离，适合同时推进好几件事。

      #普通群

      普通群里怎么分会话，由「回复模式」决定。每个机器人有一个默认值，单个群可以用 /reply-mode 覆盖：

      模式效果
      chat-topic（默认）顶层 @ 都进同一个会话；群里开出来的话题各自是独立会话
      chat整个群一个会话，话题里的消息也并进来
      new-topic每次 @ 都新开一个话题和一个新会话
      topic（也叫 shared）回复显示在话题里，但所有话题共用同一个会话
      • 查看当前模式：/reply-mode；恢复跟随机器人默认：/reply-mode inherit。
      • 机器人默认值在 Dashboard「Bot 配置」里改，或写 bots.json 的 regularGroupReplyMode（见 bots.json）。

      想在普通群里专门开一个话题做事，用 /t：

      修登录页 bug /t /repo my-app 登录按钮点了没反应，帮我查一下
      • /t 前面是话题标题，后面可以跟 /repo（选仓库）、/model（选模型）和首轮任务。
      • 只发 /t：先把话题建起来。需要选仓库时会弹出选仓卡；不需要时等你在话题里发下一条任务或 /repo，不会空跑一个会话。
      • /th 在当前群会话的工作目录里开话题；/tw 先建一个 worktree 再开话题。
      • 完整写法见 斜杠命令。

      关掉「任务执行时显示状态卡片」后，/t <内容> 仍会先回一条可见消息，让飞书马上展开话题；表情回应只是进度提示。

      #私聊

      默认整个私聊是一个连续会话，聊什么都接着上文。每个人和机器人的私聊各自独立。想换成别的方式：

      命令效果
      /reply-mode chat（默认）整个私聊一个连续会话
      /reply-mode topic每条顶层私聊消息开一个独立会话；在某条消息的话题里回复，接着那个会话聊
      /reply-mode group每条顶层私聊消息自动建一个「你 + 机器人」的专属群，会话放在群里，详见 一键新建会话群

      私聊模式对这个机器人的所有私聊生效，对应 bots.json 的 p2pMode。

      #常用操作：新开、接着聊、找回

      想做什么怎么做
      接着上次聊在同一个话题里回复（话题群）；或回到对应的群 / 私聊
      开一个新会话话题群里发新话题；普通群用 /t
      带着当前上下文并行做另一件事/fork <任务>，开一个继承完整上下文的分身话题
      找回本群还开着的话题/sessions，点「回到话题」直接跳过去
      结束会话/close。之后再发消息会开新会话
      恢复关掉的会话点关闭卡上的「▶️ 恢复会话」，或发 /resume

      #会话的一生

      阶段发生了什么
      启动中收到第一条消息，机器人正在拉起 CLI
      工作中CLI 在思考、执行，状态卡实时刷新
      等待输入这一轮做完了，可以接着发
      休眠长时间没用或常驻会话太多时，CLI 进程会退出、释放内存。话题还在，下一条消息会自动恢复上下文
      已关闭发了 /close 或点了关闭按钮。再发消息会开新会话，要接着原来的就恢复它

      每一轮都会出一张新的状态卡，上一轮的卡停在最后的状态，方便回看。卡片颜色和按钮见 实时流式卡片；休眠的触发条件和 daemon 重启会不会丢上下文，见 FAQ。

      #会话的四个名字

      「改了名，飞书里怎么没变？」因为一个会话同时有四层名字，各管各的：

      名字显示在哪儿怎么改
      飞书群名群本身的名字，群里所有人都看得到在会话里让 agent 执行 botmux chat rename "新群名"。改的是整个群，话题群里所有话题都会看到
      飞书话题名飞书话题列表改不了。飞书没有提供改话题标题的接口，话题列表总是显示话题的第一条消息。所以想要好看的标题，就在 /t 前面写好
      botmux 会话标题Dashboard、/sessions 列表在群里发 /rename <标题>；或让 agent 在会话里执行 botmux session rename "<标题>"。最长 200 字
      CLI 自己的会话名Claude Code、Codex 等 CLI 的 resume 列表改 botmux 标题时会顺手同步；CLI 不在线或不支持时就不同步，不影响 botmux 标题

      关于 botmux session rename：

      • 只能在会话里用，自动识别当前会话，不接受指定其他会话的参数，所以改不了别人的会话。
      • 标题建议写成「类型｜具体事项」，比如 排障｜支付链路超时。
      • 它只改 botmux 标题，不改飞书群名。

      agent 因为任务阶段变化主动改群名时，会加 --proactive，10 分钟内不会反复改。

      #谁能做什么（权限三层）

      层级能做什么谁有
      对话权提问、让它查日志、读代码管理员（allowedUsers）、白名单群里的所有人（allowedChatGroups）、被授权的访客（/grant）、Oncall 群成员等；blockedUsers 里的人一律不行
      操作权botmux 的斜杠命令（如 /cd、/restart、/close、/rename、/card）和卡片按钮管理员（allowedUsers）。没配任何白名单时人人都有
      管理/grant、/revoke 给别人授权，开关 Oncall 等机器人主人和管理员
      • botmux 命令默认都要操作权。少数命令只要对话权，比如 /resume。
      • 想让有对话权的人也能用某几个命令，把命令加进 bots.json 的 canTalkDaemonCommands。

      这样分层，你就能放心把机器人拉进值班群：大家都能问，但只有管理员能改会话状态，别人误点按钮也不会把会话搞乱。完整规则（额度、有效期、入群不等于授权、黑名单、授权申请卡）见 权限与授权。

      #常见困惑

      • 每次 @ 都像重新开始：在话题群里，新开一个话题就是新会话。想接着聊，请在同一个话题里回复。普通群里如果设成了 new-topic，每次 @ 也会开新会话，可以用 /reply-mode 查看。
      • 新会话不知道群里之前聊过什么：新会话从空白开始。直接跟它说「看下之前的聊天记录」即可（需要机器人有读群消息的权限，见 FAQ）。也可以让管理员在群里开 /context-sharing on，之后机器人被 @ 时会自动补上自己错过的群消息，见 多机器人协作。
      • 想换一种 CLI 但保留上下文：做不到。各家 CLI 的会话记录不通用，没法无损切换。要换 CLI 就开一个新机器人或新会话，让原来的机器人先写一份交接摘要。/relay 是把同一个会话搬到另一个群，/adopt 是把本机已有的 CLI 会话接进飞书，两者都不换 CLI。
