      #botmux

      在飞书里遥控你的 AI 编程 CLI。一条消息启动一个会话，每个会话一个独立 CLI 进程。

      botmux 是一座桥。它在你的开发机上常驻一个后台服务（daemon），负责监听飞书消息：

      • 每开一个新话题，就为它启动一个独立的 AI 编程 CLI（Claude Code、Codex、Cursor、OpenCode、Antigravity 等 30 多种）
      • CLI 每一轮的输出，实时刷新到飞书里的一张流式卡片上
      • 想直接动手时，点卡片上的按钮打开 Web 终端，在浏览器或手机里操作同一个 CLI

      人在手机上、电脑前还是终端里，看到的都是同一个会话。

      #5 分钟上手

      curl -fsSL https://raw.githubusercontent.com/deepcoldy/botmux/master/install.sh | sh
botmux setup     # 扫码建飞书应用 → 选 CLI → 选工作目录（自动配权限并发版）
botmux start     # 启动 daemon；想开机自启用 botmux autostart enable

      然后私聊机器人，或用 botmux dashboard 打开管理页拉个群，就能开始对话。

      • 安装的是自包含单文件二进制，不依赖本机 Node，支持 Linux / macOS（x64 / arm64）；Windows 请在 WSL2 中使用
      • 习惯 npm 也可以 npm i -g botmux，包里是同一份二进制
      • 在 Mac 上也可以装 macOS 桌面版，在 App 里点一下启停服务、看 Dashboard 和日志
      • 以后升级：botmux update，或重跑上面的 curl 命令（v3.18.0 之前的老版本只用 curl），然后 botmux restart

      完整步骤（含 Lark 国际版、手动配置权限、排错）见 快速接入。

      #它解决什么问题

      你的困扰botmux 怎么做
      CLI 跑在开发机上，人不在电脑前就没法看、没法管每轮输出推成飞书卡片，手机上随时查看、追问、打断；需要时开 Web 终端直接操作
      CLI 不知道飞书里发生了什么把机器人拉进群，@ 一句就在你本机的代码库里开工；/relay 能把正在跑的会话（同一个 CLI 进程、同一份 AI 记忆）搬到另一个群接着聊
      一个 Agent 不够用同一个群里放多个接不同 CLI 的机器人，@ 谁谁干活，比如让 Claude Code 和 Codex 一起 review 同一个改动

      #设计理念：直接桥接 CLI，不重造 Agent

      botmux 不重新实现 Agent 能力。记忆、上下文管理、工具调用、权限、plan mode、/ 命令、MCP 这些，交给 CLI 自己做。CLI 升级后，大多数新能力在 botmux 里直接就能用（CLI 的参数、输出格式或续聊方式变了时，对应的适配器才需要跟进）。

      你照常发人话就行。daemon 会在后台把你的消息和系统指令用结构化格式（XML 标签）分开包好，再交给 CLI，你不需要自己写任何格式。

      和「基于 Agent SDK 重新搭建」的方案比，区别主要在集成方式上：

      对比项botmux基于 Agent SDK 的方案
      桥接的是什么完整的 CLI 进程，CLI 自带的 hooks / 记忆 / plan mode / MCP / / 命令都在SDK 暴露出来的接口
      CLI 升级多数能力直接受益取决于 SDK 版本和你的集成
      记忆 / 上下文直接用 CLI 内建的取决于 SDK 或自建
      多种 CLI30 多种适配器，在配置里一键切换取决于 SDK 覆盖面
      多机器人同群多个 bot，按 @ 分派取决于实现
      直连终端用 tmux 后端时，可以 tmux attach 进真实的 CLI 进程取决于实现
