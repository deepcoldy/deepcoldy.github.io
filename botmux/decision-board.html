      #决策看板与管家

      把一个机器人设成管家：你把开发任务交给它，它去各个群里推进；遇到要你拍板的事，就写到决策看板上。你在看板上一项项写决定（可以贴图），写完点一次「提交」，这一批决定会合成一条消息送给管家，管家逐项执行，再把结果写回看板。

      你在管家群交代任务 ──▶ 管家建项、去相关群推进
                           │
                           ▼  遇到要你定的事
                    看板「待你拍板」
                           │  你写决定、贴图（自动存草稿）
                           ▼  点「提交 N 项决定」
                    一条消息送进管家会话 ──▶ 管家逐项执行，写回看板

      默认关闭。没开管家的 Bot 不会多任何文件、页面或提示词。

      #三步开启

      1. 打开 Dashboard → Bot 配置 → 选中要当管家的 Bot → 「会话」分类里的 管家 分组。
      2. 打开 设为管家，在 管家所在群 里选一个群。建议选只有你和管家两个成员的普通群；选了话题群也能用，但每批决定会作为一个新话题发出。
      3. 侧边栏出现「决策看板」。之后在管家群里给管家交代任务就行。

      只开了「设为管家」、没选群时，看板照样能看、能写草稿，但提交的决定送不出去，页面会提示你去选群。

      管家分组里的几个设置：

      设置作用默认
      设为管家这个 Bot 的会话可以用 botmux board 维护看板关
      管家所在群你在这里交代任务，提交的决定也送进这个群的会话未选
      飞书卡片拍板见下文「在飞书卡片上拍板」开
      拉新群时带上管家见下文「拉新群时带上管家」开
      只有你和一个 Bot 的群也带上管家同上关
      自动发现可以关的项见下文「自动发现可以关的项」关
      提示词预置规则只读展示；你可以在后面追加自己的规则（比如推进标准、合码标准文件路径），也可以整段替换追加

      也可以在飞书里用 /botconfig 设置：

      /botconfig set steward {"enabled":true,"chatId":"oc_…"}
/botconfig set steward {"enabled":true,"chatId":"oc_…","guideMode":"append","guideText":"推进标准：…"}
/botconfig set steward {"enabled":true,"chatId":"oc_…","decisionCards":false}   # 不发拍板卡片
/botconfig unset steward          # 关掉管家，看板数据保留

      guideMode 取 append（追加在预置后）或 replace（替换预置，此时 guideText 必填）。

      #管家怎么干活

      • 规则按需读：管家群里每轮只多一行系统提示，告诉它有看板、规则用 botmux board guide 读。规则正文不常驻在上下文里。
      • 用自己的身份推进：管家默认以自己的 Bot 身份到相关群发消息（botmux send）。对方 Bot 要能收到它的消息：在飞书开放平台开启「获取群组中其他机器人 @ 当前机器人的消息」，并在 botmux 里给管家 Bot 对话授权。
      • 拿不准的交给你：不能自己定的、不可逆的事，管家写成「待拍板」，附上两三个选项、各自后果和它的推荐。没写推进标准时，它只汇报和催办，不替你合并、关闭、发版、部署或删除。
      • 不当工作流节点：开了管家的 Bot 不会被分配去执行工作流的节点，也不能当编排 Bot。

      #定时巡检

      想让管家定期看一眼 → 在管家群里跟它说「每天 9:30 巡检一次」。它会用定时任务在管家群建一条静默任务，每次巡检：

      1. 先收口：核对看板上没结束的事项，办完的收掉，有变化的更新进展。
      2. 再发现：看最近 7 天 owner 名下没完成的 PR，以及事项关联群里的新进展，要你定的写成待拍板。
      3. 只报增量：只提醒新出现的待拍板；没有新情况就不发消息。

      巡检规则在 botmux board guide 的「定时巡检」一节，可以在自定义提示词里改（比如时间窗）。改频率、暂停、删除都用 botmux schedule。

      同一个去重键（--key）再 botmux board add 等于更新那一项；但那一项已经完成或关闭时会被拒绝，免得巡检把旧事翻回来。确实要重开，用 botmux board set。

      #自动发现可以关的项

      PR 早就合了、依赖的事早就办完了，看板上却还挂着「进行中」——打开 管家 → 自动发现可以关的项（或 "closeHints":true）后，daemon 每 5 分钟检查一次看板（不调模型）：

      情况看板上标
      挂的 PR 全部合入（没写关闭条件时的默认判断），或 --close-when 写的条件满足建议关闭
      --depends-on 写的事项都结束了；或判断关闭用的 PR 没合入就关掉了建议推进
      过了 --next-check 的复查时间，那之后这一项没有更新该看一眼
      • 只提示，不改状态：标记出现在汇总行和详情页，历史里记一条；管家核对后自己改状态。
      • 通知管家：一轮里新出现的提示合成一条消息发到管家群、送进管家会话；同一条提示只发一次。投递失败下一轮重发。
      • 收起：管家改了这一项的状态，或 botmux board set <编号> --dismiss-hint，提示收起，同一条不再出现。
      • 没写条件的项不受影响：没挂 PR、没写依赖和复查时间的事项，巡检什么都不做。
      • 查 PR 用本机的 GitHub 凭据（GITHUB_TOKEN / GH_TOKEN、~/.botmux/.env，或 gh auth login），没有时匿名查（每小时 60 次，整机共用）。开着或已关闭的 PR 每 10 分钟最多查一次（关掉的 PR 还可能重开，所以照常复查）；只有已合入是终态，合入后不再查。查不到的（不是 GitHub 上的仓库、没权限、频控）这一轮不下结论。

      #用看板拍板

      #汇总页

      三个视图：待你拍板（含「待验收」）/ 进行中 / 全部，顶部可以按标题、仓库、编号搜索。

      标记意思
      ●你上次看过之后，管家有新进展或新回复
      ✎你有没提交的草稿
      进群在飞书里打开这件事的主群；挂了几个群时标题下显示「+N 个群」
      无群：（原因）这件事确实没有群，管家写了原因
      ⚠ 缺群既没关联群，也没写原因
      💡 建议关闭 / 建议推进 / 该看一眼巡检发现的提示（见「自动发现可以关的项」），后面跟着原因

      #详情页

      从上到下依次是：

      • 群聊：这件事的全部群，主群在最前、标「主群」，每个群一个「进群」按钮；写入时没能核实的群标「未核实」。
      • 一句话说明和当前进展。
      • 要你定：问题、选项，管家推荐的那项会标出来，并写上推荐理由。
      • 你的决定：选一个选项，写说明，可以粘贴或拖入图片（png / jpg / gif / webp，单张不超过 10MB，每项最多 8 张）。
      • 历史时间线，以及关联的 PR / 会话 / 提交。

      顶部和决定框下方有「上一项 / 下一项」，顺序就是你进来时的那个列表（从「待你拍板」进来，就只在待拍板里切）；从飞书链接直接打开时，按这一项所在的视图切。切换前会先把这一项的草稿存好。

      #草稿和提交

      • 草稿自动存在服务端，不会自己发给管家。电脑上和飞书侧栏里看到的是同一份。
      • 写草稿后管家又改过这一项时，会提示「提交前再看一眼」。
      • 点「提交 N 项决定」（详情页里是「提交本项决定」或「提交（本项 + 另外 N 项草稿）」），弹窗里列出要提交的草稿；取消勾选的继续留作草稿。
      • 勾选的草稿合成一个批次，作为管家会话的一个回合送达；管家正忙时排在当前回合后面。
      • 投递失败时，页面「最近提交」里显示原因，可以点「重新投递」；daemon 重启后会自动补投没送到的批次。
      • 提交的内容也会原样发到管家群：每项的编号、标题、主群链接、选的选项和说明原文，附图跟在后面。内容太长时拆成几条消息，不删减。

      #在飞书卡片上拍板

      管家把一项改成「待拍板」或改了它的选项时，管家群里会出现这一项的拍板卡片，不用打开看板也能定：

      • 卡片上有标题、一句话现状、要你定的问题，每个选项一个按钮，管家推荐的那个标「推荐」并高亮；上面的说明框可以写几句，随选项一起提交，也可以点「只交说明」；最下面是「去看板细看」。
      • 只有你（管家 Bot 的 owner）能点，别人点了会提示没有权限。
      • 点了之后和在看板上提交一样：这一项单独成一个批次送给管家，看板的时间线和「最近提交」里都看得到。卡片随即显示「已选 X，正在交给管家」，送达后变成「已交给管家」；送不到时显示原因，到看板上重新投递，或在卡片上再点一次同一个选项。
      • 同一项只有一张卡片：之后管家改选项、你在网页上提交、管家处理完、事项关闭，都在这张卡上原地更新，不会重复发。
      • 卡片和网页都对同一项提交了时，以后提交的为准，卡片上会写明「覆盖了某批次的决定」或「随后又提交了某批次」。较早那批还没送到管家时直接作废，不再算待执行；已经送到的，管家可能已经在做，所以仍留在待执行里，新批次会提醒管家先如实标记那一条、再按新的决定执行。只在网页上连续提交的几批仍按原来的规则逐批执行。
      • 网页上那份草稿如果写在管家改选项之前（选的选项已经不在），或事项已不在待拍板，提交后照常送到管家，但不覆盖卡片上的决定。
      • 选项超过 6 个、内容太长放不下，或事项已经不在待拍板（含关闭、完成）时，卡片只显示现状和看板链接。

      不想要卡片时，在 Bot 配置的「管家」分组里关掉「飞书卡片拍板」。只对开了管家、选了管家群的 Bot 生效，其他群不受影响。

      #状态

      只有 6 个：待拍板、待验收、进行中、等待中、已完成、已关闭。更细的流程词（在审、在修、可合、等作者……）写在「阶段」里。

      #事项关联的群

      每个事项都要关联它所在的飞书群，这样在看板上点一下就能进群。

      • 建项必须带群：botmux board add 没有 --link chat=oc_… 时直接拒绝。确实没有群（只有 issue、还没开工、管家自己处理），用 --no-chat "<原因>" 写明原因；之后补上群，原因自动清掉。board set 不强制，老事项不迁移；board list 会把没群又没原因的事项标成「缺群」，方便管家补。
      • 写入时核实群：管家 Bot 的 daemon 用本机 Bot 的凭据查一下这个群。先用管家自己，查不到再依次试本机其他 Bot（只用和管家同一个 owner、同品牌、有飞书凭据的；多人共用一台机器时不借别人的 Bot；管家关了「信任同 owner 的同机 Bot」时只用管家自己）。
        • 查到了：群名当默认标签（管家给了标签就用管家的）。
        • 都查不到：拒绝写入，报错里列出各个 Bot 查不到的原因。确实要先写上，加 --allow-unverified-chat，看板上标「未核实」。
        • 凭据只在本机 daemon 进程里用，不落盘、不打印。
        • 对已有的群再 --link 一遍会重新核实：刷新群名和核实状态，不动管家起的标签。老关联可以这样补上群名。
      • 主群：一项挂多个群时（任务群加几个 PR 评审群），第一个是主群，汇总页的「进群」打开它；用 --primary-chat oc_… 换主群。

      #拉新群时带上管家

      管家要用自己的身份在群里发消息，得先在群里。所以开了管家后，botmux 每次建新群（/group、私聊转出的会话群、/fork --create、/relay --create、Dashboard 建群、botmux create-group 等所有入口），只要新群成员或发起人里有管家的 owner，建群的 Bot 就会顺手把管家拉进去。

      • 默认开启。不需要时（比如管家改用 owner 本人的身份发消息）在 管家 → 拉新群时带上管家 关掉，或 /botconfig set steward {"enabled":true,"chatId":"oc_…","autoJoinNewGroups":false}。
      • 进群不打扰：管家进群不发言、不开会话。不跑它的入群命令、入群钩子和「被拉进新群自动开工」，不拉 owner，也不参与 oncall 绑定、角色套装和 kickoff。之后有人 @ 它，才按平常的规则回应。
      • 只带对应的管家：同一台机器上几个人各有管家时，只带 owner 在新群里的那个。owner 按 union_id 认；管家没配 owner（allowedUsers 为空），或它的 daemon 还没拿到 owner 的 union_id（刚启动、缺通讯录权限）时，不带。
      • 一人一 Bot 的群默认不带：比如私聊转出的会话群、在私聊里用 /group 或 /fork --create 建的群、会议监听群。这类群不用 @ 就能接着聊，带上管家就成了两个 Bot，原来那个 Bot 要 @ 才回。按实际进群的人和 Bot 数判断。确实要带，打开 只有你和一个 Bot 的群也带上管家（需要上一项开着），或设 "autoJoinSoloGroups":true。
      • 管家本来就在要拉的 Bot 里时不重复加。拉管家失败（应用可见范围、权限等）不影响建群，只记日志；Dashboard 建群和 botmux create-group 会提示原因。

      #在飞书里打开看板

      管家给出的事项链接，在飞书电脑端点开会在会话右侧栏里打开，手机端在飞书客户端内打开。链接本身不带任何凭证，打开后怎么登录取决于部署方式：

      部署打开后怎么登录
      绑定了中心平台并开启远程访问平台飞书 SSO 自动登录；只有机器 owner 和协管者能进
      配置了 Dashboard 飞书 H5 免登（BOTMUX_DASHBOARD_FEISHU_H5_*）飞书内免登，只放行名单里的人；H5 身份只额外放开看板接口
      都没配进入 Dashboard 登录页，登录一次后飞书会记住

      #管家用的命令

      这些命令由管家在会话里自己调用，一般不用你手动敲。了解一下有助于写自定义规则：

      botmux board guide                                    # 管家规则（预置 + 自定义）
botmux board pending                                  # 已提交、还没执行的决定
botmux board list [--view decide|active|all]          # 列事项，每行带飞书里打开的链接
botmux board show <编号|key>
botmux board add <标题> --key pr:owner/repo#12 --link chat=oc_… --link pr=owner/repo#12
botmux board add <标题> --no-chat "只有 issue，还没开工"            # 确实没有群时写明原因
botmux board set <编号> --link chat=oc_… --primary-chat oc_…        # 补群 / 换主群
botmux board set <编号> --state decide --ask "要你定的问题" \
  --option "A=做法 → 结果和风险" --option "B=…" --recommend A --reason "理由"
botmux board set <编号> --unlink doc=https://旧链接 --link "doc=https://新链接|看板文档"   # 删掉 / 替换关联
botmux board history <编号> "做了什么、结果" --handled   # --handled：这项最近一批决定已执行
botmux board attach <编号> shot.png --note "复现截图"
botmux board set <编号> --close-when "item:66 done" --depends-on 66,70 --next-check +2d   # 什么时候能收
botmux board set <编号> --dismiss-hint                   # 收起巡检提示
      • --link kind=ref|标签：最后一个 | 之后是标签（网址里本身有 | 时写成 %7C）。
      • --link 只追加；填错的用 set <编号> --unlink kind=ref 删掉。
      • 群查不到又确实要写，加 --allow-unverified-chat。
      • --close-when："pr:owner/repo#12 merged"、"item:66 done"、manual（只由管家判断，挂了 PR 也不按默认规则提示）、auto（去掉，回到默认）。--depends-on 整组替换，none 清空。--next-check 写 +2h / +3d / +1w 或带时区的时间（2026-11-10T09:30+08:00），none 清空。
      • 完整参数见 botmux board --help。

      #数据存在哪

      看板存在 <数据目录>/decision-board.sqlite（整机一个文件，按管家 Bot 分开），截图存在 <数据目录>/decision-board/<app_id>/files/。第一次用看板时才创建。关闭管家不会删除看板数据。
