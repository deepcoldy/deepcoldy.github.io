      #@ 策略（mention-mode）

      在普通群里，bot 默认只回应明确 @ 它的消息。「@ 策略」决定什么时候可以不用 @。

      它只管「这条消息是不是在叫这个 bot」，不管权限：免 @ 不等于免授权，没有对话权的人照样会被拦（见权限与授权）。

      #先选一个模式

      模式Dashboard 里的名字效果适合
      always（默认）必须 @每次都要 @ 本 bot 才回大群，最安静
      topic话题内免 @顶层消息仍要 @；在本 bot 已接管的话题里回复不用再 @话题里反复追问
      never全群免 @群里有对话权的人发什么都回，包括没 @ 的顶层新消息（会直接新建或续接会话）专人专用群、值班群
      ambient免 @，让位和 never 一样免 @；但如果消息 @ 了别的成员（人或 bot）而没 @ 本 bot，就保持安静，因为那是在叫别人多 bot / 多人协作群里的「默认应答者」

      补充两点：

      • @所有人 不算「叫别人」，ambient 下照样回应。
      • topic 模式下，在话题里回复时如果只 @ 了别人，bot 同样会让路。

      #怎么设置

      @ 策略有两层，群级设置优先：

      层级作用范围在哪改
      Bot 默认这个 bot 所在的所有普通群Dashboard「Bot 配置 → 会话 → 群聊回复条件」，或 bots.json 的 regularGroupMentionMode
      单个群只影响当前这个群在群里发 /mention-mode（写入 bots.json 的 chatMentionModes）

      #在群里用命令改

      在普通群里发（多 bot 群要 @ 到具体那个 bot）：

      @bot /mention-mode status     # 查看当前群用的是哪种
@bot /mention-mode always
@bot /mention-mode topic
@bot /mention-mode never
@bot /mention-mode ambient
      • 查看（status 或不带参数）：有对话权即可。
      • 修改：需要操作权（owner / allowedUsers）。
      • 改完立即生效，只影响这个群，不动 bot 默认值。
      • 把群设成和 bot 默认相同的值，等于「恢复跟随默认」：以后 bot 默认改了，这个群也跟着变。（开了 signedChatDefaults 的 bot 例外：设置会原样保存，见文末「可信建群服务」。）

      #哪些群能设

      只有普通群能设：

      • 私聊：天然不需要 @。
      • 话题群：本来就是话题形态，命令会回复「无需设置」。
      • /group 建出来的会话群：由 bot 自动管理，拒绝修改。

      #为什么设了 always，它不 @ 也回？

      「必须 @」是默认主规则，但还有一组并列的例外，命中任意一条就会回应。觉得「它怎么不听话」时，基本是下面这些情况：

      #情况说明
      1续接本 bot 的话题回复这条回复所在的话题已经确定是冲着本 bot 来的（比如话题内回复被折回群会话），直接放行
      2替身触发bot 开了替身模式，消息 @ 了被代答的对象（见下文「替身模式」）
      3消息监听命中Dashboard「消息监听」里配的监听规则匹配了。这条不看 @ 策略，也不走常规对话权限，监听器有自己的发送者过滤
      4模式是 neverbot 默认或本群被设成了全群免 @
      5模式是 ambient，且消息没 @ 别人
      6模式是 topic，且消息在本 bot 接管的话题里
      7免 @ 斜杠命令在 Dashboard「Bot 配置 → 会话 → 免@ 斜杠命令」里列出的命令（比如 /solve），在普通群里裸发也会触发。只放开列出的命令，不是全群免 @
      8内置免 @ 命令/dash 和 /dashboard link 在任何群里都不用 @
      9群负责人本 bot 被设成了这个群的负责人（默认接待者），群里顶层未 @ 消息由它接。需要先在「Bot 配置 → 会话」里打开「群负责人（默认接待者）」。详见斜杠命令里的「群负责人」一节
      101 人 1 bot 群群里只有你和这个 bot，默认不用 @。可以关掉，见下一节

      几点细节：

      • 除了消息监听（第 3 条），其它情况都要求发送者有对话权。
      • 第 7、8、9 条也遵守「点名让路」：消息开头先 @ 了别人，bot 不接。但 /solve @某人 这种 @ 写在命令后面的，算命令参数，照常触发。
      • 多 bot 群里想避免互相抢话，优先用 ambient：谁被点名谁回答。

      小提示：发出去才发现忘了 @？用飞书消息菜单里的「修改」补上 @ 本 bot，同样能触发。

      #替身模式：@ 某人时由 bot 代答

      替身模式让 bot 当某些人的「替身」：群里有人 @ 了这些人（没 @ bot），bot 会代他们回答。适合值班人、项目负责人这类经常被 @ 提问的人。

      #怎么开

      在 Dashboard「Bot 配置 → 会话 → 替身模式」里打开「启用替身触发」，再添加替身对象。保存后立即生效。

      • 替身对象可以直接填邮箱，保存时会自动解析成本应用的 Open ID；解析失败的会标红，不会存进去。
      • 也可以直接填 Open ID、User ID 或 Union ID。Open ID 必须属于这个 bot 的应用，别的应用的 Open ID、不在应用通讯录可见范围内的人都会被拒绝。
      • 开启时至少要有一个能匹配的对象，否则保存不了。

      发消息的人仍然要有对话权，替身模式不放宽权限。想让群里所有人都能 @ 替身对象提问，和 Oncall 模式一起用。

      #哪些消息会触发

      • 只认发送者亲手 @ 的文字和富文本消息。转发的卡片、合并转发里带出来的 @ 不算。
      • @ 了替身对象，但正文以 / 开头（斜杠命令）的，不触发。
      • 普通群：替身回合进这个群的群会话，回复挂在触发消息下面。
      • 话题群：替身回合进该话题自己的会话（没有就新开一个），回复留在原话题里。

      #配置项

      Dashboard 里的每一项都对应 bots.json 里这个 bot 条目的 substituteMode：

      {
  "substituteMode": {
    "enabled": true,
    "targets": [
      { "openId": "ou_example", "name": "值班同学" }
    ],
    "disclosure": "prefix",
    "replyMode": "thread",
    "chats": [],
    "excludedChats": ["oc_example"],
    "topicGroups": true,
    "topicActiveSessionTrigger": true,
    "disableControlCard": false
  }
}
      字段Dashboard 里的名字含义
      enabled启用替身触发总开关。关掉时替身对象等配置会保留，下次打开不用重填
      targets替身对象被代答的人。每项写 openId / userId / unionId 之一，name 是给 AI 看的显示名（可选）
      disclosure披露方式prefix（默认）：要求 AI 回答时说明自己在替谁回答；none：不额外要求说明
      replyMode回复方式只影响普通群。thread（默认）：在触发消息下开话题回复；quote：引用触发消息回复，不开新话题
      chats生效群聊白名单。留空表示所有群都生效；填了就只在这些群触发
      excludedChats黑名单群聊列出的群里永不触发，群内 /substitute on 也打不开。同时出现在白名单和黑名单里的群，以黑名单为准
      topicGroups话题群支持默认开。设为 false 后只在普通群生效
      topicActiveSessionTrigger已有活跃会话的话题里也触发默认开。设为 false 后，话题里已有本 bot 的会话时，@ 替身对象视为转交给别人，bot 保持安静
      disableControlCard发送 owner 控制卡片普通群的替身会话启动后，默认私信 owner / allowedUsers 一张控制卡（打开终端、重启、关闭）。设为 true 不发。话题群照常有流式卡片，不另发

      几点注意：

      • 手写 bots.json 时，targets 里只写邮箱匹配不到人：飞书的 @ 里不带邮箱。邮箱只会被当作备注保留；如果开着替身模式、却没有一个对象带 openId / userId / unionId，整段 substituteMode 在加载时会被忽略。需要按邮箱填，请在 Dashboard 里保存，让它解析成 Open ID。
      • 手动改完执行 botmux restart 生效。
      • 黑名单群里，@ 替身对象的消息会被直接忽略，不会再走其它免 @ 规则。直接 @ bot 照常回答。

      #单个群临时开关

      替身模式默认在所有生效的群里开着。想在某个群临时关掉，在群里 @ bot 发：

      @bot /substitute status     # 查看本群是否开启
@bot /substitute off        # 本群关闭
@bot /substitute on         # 本群重新打开
      • 查看不限人，开关需要操作权（owner / allowedUsers）。
      • 普通群和话题群都能用，私聊不支持。
      • 群在黑名单里，或者话题群但 topicGroups 关了，命令会直接告诉你本群用不了，不会假装开启成功。

      #关掉「1 人 1 bot 群免 @」

      群里只有 1 个人和 1 个 bot 时默认免 @。想让这类群也按 @ 策略走，在对应 bot 的 bots.json 条目里配置：

      {
  "regularGroupMentionMode": "always",
  "soloGroupMentionBypass": false,
  "chatSoloGroupMentionBypass": {
    "oc_example": true
  }
}
      字段含义
      soloGroupMentionBypassbot 级开关。不写或 true：保持免 @；false：关掉这个例外
      chatSoloGroupMentionBypass按群覆盖。显式 true / false 优先于 bot 级开关；删掉某个群的条目就恢复继承

      上面的例子：只有 oc_example 这个群保留免 @，其余群都关掉。如果只想关一个群，就保留 bot 默认，在映射里把那个群设成 false。

      手动改完执行 botmux restart 生效。

      关掉之后：

      • 是否回应由生效的 @ 策略决定（群级优先）：always 要 @；topic 仍可在已接管的话题里免 @ 续聊；never / ambient 照旧。
      • 在 always / topic 下，没 @ 的顶层文字、图片不会再因为「群里人少」就触发会话。
      • 开关对普通群和话题群都生效，不影响私聊；权限检查和「点名让路」照常。

      这个开关只关掉「人少」带来的隐式例外。消息监听、免 @ 命令、替身、入群 / 新话题自动开工这些显式配置各自独立。想要严格只认 @：把开关设为 false，把群的 @ 策略设为 always，再检查这个群有没有开别的触发方式。

      另外，判断「是不是 1 人 1 bot」用的是群成员人数。消息里 @ 了别的成员时，bot 会重新查一次人数，避免刚拉进新 bot 时旧 bot 抢话。被 @ 的人不在群里（飞书允许 @ 群外的人）、重查后仍是 1 人 1 bot 时，照常免 @。

      #进阶：可信建群服务

      如果你的部署接入了可信建群服务，并在 bots.json 里开了 signedChatDefaults，由该服务创建的群会默认按 ambient 处理。这时的优先级是：群级 /mention-mode 设置 → 建群服务声明的 ambient → bot 默认。它同样只影响「要不要 @」，不放宽任何权限。

      相关：回复落到新话题还是当前会话，由 /reply-mode 控制，见斜杠命令。
