      #飞书文档评论监听（/watch-comment）

      让机器人「住进」一篇飞书云文档：你在文档评论里提问或提要求，AI 读文档、干活，然后把答复直接回到这条评论的讨论串里。不用离开文档，也不用切到群里。

      适合这些场景：

      • 边看设计文档边问「这一段和代码实现一致吗？」
      • 让 AI 帮你改写、补充、检查文档里的某一段
      • 开会前把文档交给 AI 预读，会上大家在评论里直接问

      #最快上手：在评论里 @机器人

      什么命令都不用发。打开任意一篇机器人能访问的飞书文档，在评论里 @机器人 写上你的问题即可。

      • 机器人收到后，会在你的评论上加一个「Typing」表情表示正在处理，答复发出后自动撤掉。
      • 答复以机器人身份发在原评论的讨论串里，并 @ 回提问的人。
      • 这篇文档会自动登记为「仅 @ 机器人才回复」的监听，之后在这篇文档里继续 @机器人 都会被处理。
      • 文档里每条评论串各自一个独立会话，互不串话。

      如果 @机器人 的不是 bot owner（机器人的主人），机器人同样会立即回复，但前提是它能先私信 owner 一条通知：谁在哪篇文档 @ 了它。通知发不出去（或 bot 没配 owner）时，这次不回复，自动登记也会撤销。这是「通知，不需要审批」：owner 总会知道，但回复不用等 owner 点头。不想再在某篇文档里回复，owner 发 /watch-comment off <文档链接> 即可。

      这条「零命令」路径依赖飞书把评论事件推给机器人。如果第一次 @ 没反应，请先检查下面的「一次性准备」，或改用 /watch-comment 显式登记。

      #绑定到某个话题：/watch-comment

      想让评论和某个飞书话题共用同一个 AI 会话（比如这个话题已经在聊这个项目），在该话题里发：

      /watch-comment <飞书文档链接> [--dir <本地项目路径>] [--all | --mentions-only | --owner-mentions]

      发完之后：

      1. 话题里如果还没有 AI 会话，会立即创建并启动 CLI；
      2. AI 先读一遍文档、建立上下文，然后进入「等评论」状态；
      3. 之后文档里符合条件的评论都会喂进这个会话，答复回到原评论串；
      4. 状态卡、终端链接等卡片仍发在这个话题里。

      想结合本地代码回答，用 --dir 指定项目目录；不写时沿用话题会话当前的工作目录。都没有时 AI 只根据文档内容回答，回执里会提示你可以 /cd <项目目录> 补上。

      /watch-comment 的所有用法（登记、list、off）都只有 bot owner 能用。其他人只能在文档里 @机器人 触发回复。

      #命令一览

      命令作用
      /watch-comment <文档链接> [--dir <路径>] [模式]登记监听，并绑定到当前话题会话
      /watch-comment list在会话里：看当前会话监听的文档；没有会话时：看本 bot 的全部文档监听
      /watch-comment off <文档链接>停止监听这一篇
      /watch-comment off 或 off all停止当前范围（当前会话 / 本 bot）的全部监听

      支持飞书云文档（docx）和知识库（wiki）链接。

      #哪些评论会触发：三种模式

      模式命令参数谁会触发 AI适合
      仅 @ 机器人（默认）--mentions-only评论里 @机器人大多数文档，最安静
      @ 负责人才回复（替身）--owner-mentions评论里 @ 了监听负责人（发 /watch-comment 的人）或 @机器人让机器人替你回答别人 @ 你的问题
      所有新评论--all文档下任何新评论，不需要 @机器人专用文档

      几点说明：

      • 「替身」和「所有新评论」两种模式靠机器人每 5 秒左右读一次评论列表发现新评论，所以可能有几秒延迟；真正 @机器人 的评论仍会即时送达，两条路不会重复处理。
      • 切到这两种模式时，机器人只处理之后的新评论，不会把旧评论翻出来重答。
      • 自动登记（零命令路径）总是「仅 @ 机器人」。想换模式，重新发一次 /watch-comment <链接> --all（或别的参数），或在 Dashboard 里改。Dashboard 里只能选「仅 @ 机器人」和「所有新评论」，替身模式只能用命令设置。
      • 三个模式参数只能选一个，同时写多个会报错。

      #设置默认模式

      新登记的监听默认用哪个模式，可以按机器人设置：Dashboard → Bot 配置里的「文档订阅触发范围（默认）」，可选「仅评论 @ 本机器人才触发」或「所有新评论都触发」。

      对应 bots.json 字段 docSubscribeDefaultMode：写 "all" 表示所有新评论，不写就是仅 @ 机器人。

      #给文档固定项目目录

      希望某篇文档一触发就在固定项目目录里干活，可以在 bots.json 里配 docRepoMap，键是文档 token，值是本地绝对路径：

      {
  "docRepoMap": {
    "<文档 token>": "/home/me/my-repo"
  }
}

      docRepoMap 只对没绑话题的监听生效（零命令自动登记、Dashboard 里登记的）。绑在话题上的监听用的是话题会话的工作目录，想换目录就用 --dir 或在话题里 /cd。

      #在 Dashboard 里管理

      Dashboard 左侧导航有一个 「文档监听」 页，可以不用命令就完成管理：

      • 看列表：每篇被监听的文档、所属机器人、工作目录、触发模式；
      • 看运行情况：最近活动时间、最近投递时间、累计投递次数，以及「最近一条评论为什么没被回复」；
      • 改模式 / 停止监听：直接在卡片上切换触发范围（「@ 本机器人才回复」或「所有新评论」），或点「停止监听」；
      • 新登记：粘贴文档链接（或 token），选机器人和触发范围，可选填工作目录，点「开始监听」。新文档不绑任何话题，第一条符合条件的评论到来时才创建会话；已经绑在某个话题上的文档，这里只更新模式和工作目录，评论仍回到原话题；
      • 认出来源：由别人在文档里 @ 出来的自动登记会有标记，方便 owner 审查。

      当有评论没处理成功时，Dashboard 的总览页和会话页顶部会出现「文档评论失败记录」，展开可看原因并跳到「文档监听」页。在评论区里，机器人没能处理的 @ 也会留下一个错误表情，方便提问的人知道要重试。

      #AI 能看到什么

      每条评论喂给 AI 时，会一起带上：

      • 文档链接；
      • 局部评论（选中一段文字发的评论）对应的原文；
      • 这条评论串里之前的讨论。

      问题需要看完整正文时，AI 会被要求先用可用的飞书文档工具读文档，而不是凭空猜。

      #答复怎么回到文档

      • 默认以机器人身份回复在原评论串里，第一段 @ 回提问的人；
      • 超长答复会自动拆成多条评论；
      • 少数评论（比如已解决、或文档设置不允许回复）不能挂回复，机器人会改为新建一条全文评论作为答复，保证答案总能落到评论区；
      • 如果机器人自己没有这篇文档的访问权限，会退回用授权用户的身份发表。想让答复始终显示为机器人，请把文档共享给机器人；
      • 文档评论只是纯文本通道，按钮、卡片、终端链接等仍走飞书话题（零命令自动创建的文档会话不发卡片，只在评论里回复）。

      #一次性准备（飞书开放平台）

      /watch-comment 不需要 User Token。机器人用应用身份读评论、发回复，只需要在飞书开放平台后台给应用做两件事：

      1. 权限管理：开通 docs:document.comment:read（读评论）、docs:document.comment:create（发评论/回复），监听知识库文档还要 wiki:wiki:readonly，然后发布版本；
      2. 事件订阅：添加 drive.notice.comment_add_v1（云文档新增评论）事件，订阅方式选长连接。

      机器人已有文档监听时，启动自检会检查这些权限，缺了会私信管理员。事件订阅飞书没法自动检测，自检只会提醒你去确认。

      #生命周期

      • 在话题里 /close 关闭会话时，绑定在它上面的文档监听会一起移除；
      • daemon 重启后，监听和「所有新评论 / 替身」模式的读取进度都会自动恢复，不会重答旧评论；
      • 一篇文档同一时间只绑一个会话：在另一个话题里对同一篇文档再发 /watch-comment，会把它改绑过去，回执会提示你；
      • 一个会话可以同时监听多篇文档。

      #旧命令 /subscribe-lark-doc

      /subscribe-lark-doc 是早期的方式，保留给需要它的人：它要求文档权限的 User Token，调用飞书的「逐文件订阅」接口，再把订阅绑到当前会话。缺 Token 时命令会给出授权链接，授权后重试即可。

      命令作用
      /subscribe-lark-doc <文档链接>用 User Token 订阅这篇文档，并绑定当前会话
      /subscribe-lark-doc list查看本会话已订阅的文档
      /subscribe-lark-doc off退订本会话的所有文档

      新用法优先用 /watch-comment。只有在零命令路径收不到事件、又需要强制走飞书逐文件订阅时，才需要 /subscribe-lark-doc。用它订阅的文档在 /close 时会调用飞书接口退订。
